## 审查发现

### [P1][F1] nonce 缓存饱和等服务端容量限制被表达为设备身份认证失败

位置：[core/nonce.go:35](../../core/nonce.go#L35)、[core/nonce.go:45](../../core/nonce.go#L45)、[api/device_api.go:102](../../api/device_api.go#L102)。跨端相关行为见客户端 `crates/engine/src/sync.rs:143–178`。

`NonceCache.Claim()` 对重放拒绝和缓存饱和统一返回 `false`，API 均回答 401。客户端将普通 401 计入身份失败，达到阈值即清除本地设备身份。服务端短时容量不足因此可能被错误解释为已注册设备身份失效，放大为需要重新注册的持久故障。

建议在缓存内部区分认证失败与容量耗尽，容量耗尽返回可重试的服务不可用响应，并保留有效窗口内已登记的 nonce。对客户端而言，服务端暂时无法处理请求不能改变已注册身份。现有反向代理承担按设备/IP 限速的决定已接受，本项讨论的是服务端及客户端错误语义，不要求再增加重复限速器。

### [P2][F2] 设备认证主体只绑定可复用标识，未绑定实际验证使用的公钥

位置：[api/device_api.go:81](../../api/device_api.go#L81)、[api/device_api.go:97](../../api/device_api.go#L97)、[api/device_api.go:106](../../api/device_api.go#L106)、[app/device.go:359](../../app/device.go#L359)、[app/heartbeat.go:66](../../app/heartbeat.go#L66)、[db/device.go:240](../../db/device.go#L240)。

设备签名经过当前读出的 `Pubkey` 验证之后，认证主体只保留 public ID 和 device ID。应用层锁内以及数据库条件观察写入仅复核这两个标识。它们可以在设备重新绑定时发生变化，也可能重新出现，因此不能完整表达「此次请求经哪一代密钥认证」。

建议将认证主体与实际验证使用的公钥或不可复用的绑定代次关联，并在应用层一致性边界复核。注册的签名证明也遵循相同判据。密钥/绑定变化后，属于旧绑定的在途认证结果应失效。此项为静态身份一致性审查，未构造主动攻击流程。

### [P2][F3] 种子签发结果未完整验证与意图记录的身份及有效期关系

位置：[app/credential.go:69](../../app/credential.go#L69)、[app/credential.go:75](../../app/credential.go#L75)、[app/credential.go:83](../../app/credential.go#L83)、[app/credential.go:203](../../app/credential.go#L203)、[app/credential.go:233](../../app/credential.go#L233)、[db/credential.go:41](../../db/credential.go#L41)。

签发前控制面生成 ID 并写入意图行，随后由 CLI 返回 ID、私钥与到期时间。`generate()` 仅判断到期时间能否解析及私钥是否为空，未核对返回 ID 与请求意图一致，也未判断有效期的合法范围。之后本地更新使用原意图 ID，响应返回 CLI 给出的 ID。

发生 CLI 版本变化、异常输出或签发结果不一致时，种子侧凭据、控制面记录和客户端收到的凭据可能不同源。这违反了意图行方案的核心契约。建议在签发通道适配层验证完整返回值，确认 ID、密钥形状与有效期都符合请求及当前协议，经校验的单个结果用于完成意图行和构造响应。异常结果进入现有补偿及可观测错误路径。

### [P2][F4] 设备锁等待没有请求取消语义，可能占用共享业务容量

位置：[app/locks.go:25](../../app/locks.go#L25)、[app/locks.go:36](../../app/locks.go#L36)、[app/heartbeat.go:66](../../app/heartbeat.go#L66)、[app/credential.go:290](../../app/credential.go#L290)、[api/api.go:232](../../api/api.go#L232)。

`keyedLock` 使用阻塞的 `sync.Mutex.Lock()`，无请求上下文。心跳、删除、重绑和签发在拿到锁以后才使用调用方的 context。外部签发或撤销较慢时，同设备的请求排队；其中已经结束或取消的请求仍保持 HTTP 并发闸门占用，并在取得设备锁后进入业务路径。

建议设备锁提供取消感知的等待方式，无法继续的请求释放等待引用并立即返回。进入具备写副作用的业务操作前检查请求是否仍有效。保留按设备串行、锁条目引用回收及全局 HTTP 闸门。该改进与反向代理的限速职责独立。

### [P2][F5] 发布验收与客户端安装器对同一归档的合法域不一致

位置：[app/settings.go:48](../../app/settings.go#L48)、[app/settings.go:53](../../app/settings.go#L53)、[app/settings.go:448](../../app/settings.go#L448)、[app/settings.go:480](../../app/settings.go#L480)。客户端对应 `crates/launcher/src/install.rs:51–60, 711–747`。

控制面允许 4096 个成员及 512 MiB 解压量，启动器限制为 1024 个成员及 256 MiB。两端的归档类型判断也不同，控制面读取成员名称和摘要但没有执行与启动器相同的普通文件类型检查。签名和文件集合校验可以通过的工件仍可能超过目标端安装契约。

建议统一发布及消费端的归档合法域和资源限额。控制面在接收发布记录之前验证目标安装器能够接受的工件结构，保持 MESH3、MESH4 及文件集合的既定签名语义。常规出包流程加入与两个消费入口共同使用的契约检查。无需新增第三套包格式。

### [P2][F6] 新增发布槽位 CHECK 约束尚未进入结构验证

位置：[db/db.go:49](../../db/db.go#L49)、[db/db.go:60](../../db/db.go#L60)、[db/db.go:208](../../db/db.go#L208)、[db/release.go:80](../../db/release.go#L80)。

新的 release 表依赖两项 CHECK 语义，约束 slot 合法值及启动器行的说明和自动更新字段。`tableEntries()` 比较列属性、命名索引及隐式 UNIQUE 结构，没有检查 CHECK。列和索引相同但缺少此约束的数据库仍可通过启动结构校验。

`slotRow.attach` 已明确依赖表约束，对于启动器行不读取额外字段。因此数据库迁移若遗漏约束，代码验证及模型假设不能构成完整闭环。

建议对当前 DDL 新增的实际数据约束执行可比较的结构验证，或在启动验证阶段通过可回滚的独立约束检查确认行为。保留参考数据库为单一事实来源及现有显式迁移策略，避免引入完整 SQL 解析框架。已明确接受的部分索引谓词文本取舍不影响本项。

### [P3][F7] `DecodeJSON` 仅验证首个 JSON 值，未确认请求体结束

位置：[httpx/response.go:36](../../httpx/response.go#L36)、[httpx/response.go:41](../../httpx/response.go#L41)。

新的统一解码器启用了未知字段拒绝及请求体上限，但一次 `Decode(dst)` 成功后立即返回。额外的请求体内容不在已验证 JSON 值内，后续数据也未要求全部通过大小限制读取。与 API「一份有界、完整的 JSON 请求」的预期不一致。

建议成功解出业务值后明确确认请求体只剩合法空白并已到 EOF，保证总请求体限制实际作用于完整内容。统一输入错误映射，测试完整请求、尾随非空内容及超过上限的请求。

### [P3][F8] HTTP 响应写入没有独立期限，长尾连接的收尾策略不完整

位置：[main.go:39](../../main.go#L39)、[main.go:165](../../main.go#L165)、[main.go:189](../../main.go#L189)、[httpx/response.go:17](../../httpx/response.go#L17)、[api/api.go:232](../../api/api.go#L232)。

设备面与管理面服务器均设置读头、请求读取和空闲超时，但没有响应写入时限。HTTP 闸门释放发生于 handler 返回之后。响应传输异常可能延长 handler 生命周期并占用有限的并发预算。

建议为响应传输设定明确的时间边界，并与发布下载、凭据操作可能需要的后端总时限协调。发布等耗时动作避免使用过短且覆盖整个业务时间的统一写截止时间。核对部署反向代理与服务端超时的职责。
