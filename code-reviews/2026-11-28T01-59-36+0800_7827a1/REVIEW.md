## 2. 本轮发现

### [P0][F1] 凭据生命周期缺少设备级一致性边界

- 位置：[app/credential.go:157-185](../../app/credential.go#L157-L185)、[credential.go:190-245](../../app/credential.go#L190-L245)、[app/device.go:267-279](../../app/device.go#L267-L279)、[device.go:305-345](../../app/device.go#L305-L345)、[api/device_api.go:328-337](../../api/device_api.go#L328-L337)、[device_api.go:385-426](../../api/device_api.go#L385-L426)。
- 条件：正常心跳签发/确认与管理端签发、撤销、删除、重绑或配置身份变更重叠，或种子签发成功后持久化失败。
- 结果：设备存在性和身份、最新凭据、冷却、外部种子操作及数据库写入分属独立步骤。同一设备的生命周期没有线性化点，无法保证删除或换绑后旧身份的凭据全部撤销，也无法保证最新凭据的确认不会影响另一轮合法签发。种子成功而控制面记录失败时也缺乏明确恢复材料。这违背根 `DESIGN.md` 中可撤销性及冷却不变量。
- 修复：将设备身份代次、凭据签发决策、确认与撤销收敛为一个明确的设备级串行协议；外部签发与数据库需要可重试、可对账的结果表示。为删除、重绑、身份变更、冷却、确认和失败恢复建立统一不变量。修复方的回归测试应验证合法并发管理与心跳下不存在游离凭据、错撤或重复签发，并确保失败不会被报告为成功。与客户端 F8 共同核对“确实已加载”语义。

### [P0][F2] 已绑定设备一次性令牌的核验与消耗非原子

- 位置：[api/device_api.go:140-165](../../api/device_api.go#L140-L165)、[device_api.go:199-226](../../api/device_api.go#L199-L226)、[app/device.go:252-261](../../app/device.go#L252-L261)、[device.go:315-337](../../app/device.go#L315-L337)。
- 条件：已绑定设备依据注册令牌重新读取配置时发生并发请求、令牌轮换或持久化失败。
- 结果：已绑定分支将证明查询、消费、返回配置拆成多个操作，消费错误仅记日志。一次性消费以及配置返回与授权成功之间缺乏原子关联。首次绑定分支已在 `database.Update` 内检查当前令牌及到期时间，两条入口的安全约束因此不同。
- 修复：复用统一的令牌验证/消费事务，同时校验绑定身份及公钥，只有消费成功才按当前绑定返回配置。签名认证分支仍可独立处理。测试应约束令牌只能成功消费一次、轮换状态不会被旧操作覆盖，以及持久化失败不会释放受保护的响应内容。

### [P2][F3] 签名时间窗与设备字段缺乏完整合法域和资源约束

- 位置：[core/signing.go:26-48](../../core/signing.go#L26-L48)、[core/nonce.go:28-57](../../core/nonce.go#L28-L57)、[api/device_api.go:62-103](../../api/device_api.go#L62-L103)、[device_api.go:292-309](../../api/device_api.go#L292-L309)。
- 条件：设备上报字段超出协议期望的形状或长度，或时间戳处于表示范围的极端边界。
- 结果：时间窗使用有符号 `Duration` 的绝对值计算，未覆盖饱和值边界；签名字段按文本拼接，未统一限制字段合法域。缓存按 nonce 原始字符串存储且无条目数限制，心跳观测字段直接进入持久化。1MiB 请求上限不能替代单字段和共享状态的预算。
- 修复：在验签与状态修改前统一设备协议值域，使用直接的时间区间比较，给重放缓存和上报字段明确容量/长度界限；缓存饱和应按确定且安全的策略处理。两端共同定义契约，验证正常时间窗、极端时间边界和字段限制。

### [P2][F4] 发布路径只能证明外层签名和部分清单形状

- 位置：[app/settings.go:205-247](../../app/settings.go#L205-L247)、[settings.go:408-432](../../app/settings.go#L408-L432)、[settings.go:447-510](../../app/settings.go#L447-L510)、[signing/signing.go:98-127](../../signing/signing.go#L98-L127)。
- 条件：发布者提交经过外层授权的工件，但打包过程中内层签名缺失、文件内容与清单不一致或归档不完整。
- 结果：服务端 `packageManifest` 没有 `signature` 字段，且读取第一个清单后仅消费剩余压缩字节计算外层摘要，不能确认归档完整、清单真实性和实际文件集合。控制面可以接受客户端启动器必然拒绝的工件。这里不削弱设备验签的最终信任锚，但把可提前发现的发布错误推迟到设备更新阶段。
- 取舍：`docs/contract/updates.md:97` 明确控制面只验包签名，因此这是发布验收范围的工程缺口。请修复方明确回应是否继续接受该故障模式，或把真实性和安装可接受性预检纳入发布契约。若收敛，建议复用同一清单验证规则并保留受限解包预算，验证正常出包与合法签名但不完整的发布工件。

### [P2][F5] 已有数据库的列名校验不足以确认数据契约

- 位置：[db/db.go:98-106](../../db/db.go#L98-L106)、[db.go:115-167](../../db/db.go#L115-L167)、[db.go:203-247](../../db/db.go#L203-L247)。
- 条件：运维手工完成库结构调整，列名与当前代码一致，但约束、类型、默认值或索引有偏差。
- 结果：`tableColumns` 读出了类型、非空、默认值、主键等信息却只保留名字。相同名字的索引也不一定会被 `CREATE INDEX IF NOT EXISTS` 修正。`verifySchema` 因此可能通过无法保证设备 ID 唯一性、槽位约束及默认值语义的库。既已取消自动兼容，这个启动检查应成为可靠的部署失败判据。
- 修复：以现有内存参考数据库为事实来源，比对影响当前业务的列、约束、索引及必要对象；仅检查声明范围内的契约，避免引入手工维护的第二份 schema。对列名一致但结构约束错误的测试库断言启动拒绝。

### [P2][F6] 签发子进程的失败输出与清理时间没有有效上限

- 位置：[app/credential.go:26-51](../../app/credential.go#L26-L51)、[credential.go:89-107](../../app/credential.go#L89-L107)、[credential.go:208-222](../../app/credential.go#L208-L222)。
- 条件：CLI 失败时持续产生错误输出，或子进程及其继承的管道没有按时退出。
- 结果：stdout 有 64KiB 限制，stderr 却是无界 `strings.Builder`；`CommandContext` 只设置主进程超时，未对管道等待建立显式上限。错误信息随后进入日志。单次签发/撤销的总时限不能单独证明内存和生命周期受限。
- 修复：统一两条输出流的预算并记录截断状态、约束进程及管道清理时限，低成本失败时返回稳定错误。测试使用受控 CLI 夹具验证异常退出和有限输出；管理端失败日志避免包含私钥等敏感内容。

### [P3][F7] 配置身份分类解析重复，解析失败映射为正常身份

- 位置：[app/config.go:35-71](../../app/config.go#L35-L71)、[app/credential.go:168-176](../../app/credential.go#L168-L176)。
- 条件：设备配置读取成功但 TOML 结构非法，或者刷新多个设备详情和列表。
- 结果：签发路径明确拒绝解析失败，显示路径却默认返回 `IdentityCredential`，将非法配置展示为合法的凭据节点。合法配置在 `ConfigFactsOf` 中先 decode 一次，再调用 `identityOf` decode 一次，每轮设备列表都重复工作。身份提取规则与显示所需字段也互相耦合。
- 修复：一次解析生成共享的事实对象，显式区分解析错误和正式/凭据身份；管理面可显示该设备错误而保留其它列表项。前端类型同步表达错误状态，签发使用同一判据。

### [P3][F8] 同一会话中旧设备列表响应可覆盖新结果

- 位置：[frontend/src/App.vue:79-102](../../frontend/src/App.vue#L79-L102)、[App.vue:150-165](../../frontend/src/App.vue#L150-L165)。
- 条件：同一登录会话的轮询、手工刷新或新建设备后的刷新重叠，返回顺序发生变化。
- 结果：会话代次能丢弃旧登录会话的响应，同一会话所有列表请求却共享同一个代次。较旧的响应晚到时会覆盖已更新的设备及分组列表，表现为页面短暂回退或新设备消失。
- 修复：建立同一资源的请求代次，或使列表加载单飞并明确保留下一轮刷新请求。只让最新有效结果更新状态，测试逆序完成及换会话的响应。

### [P3][F9] 注册令牌的声明、生成及接受合法域不一致

- 位置：[app/device.go:26-31](../../app/device.go#L26-L31)、[device.go:130-144](../../app/device.go#L130-L144)、[device.go:410-413](../../app/device.go#L410-L413)、[app/settings_test.go:64-87](../../app/settings_test.go#L64-L87)，以及 mesh 根 `docs/contract/device-api.md:183-185`。
- 条件：对注册令牌做早期形状校验，或未来生成实现与其他客户端按文档独立实现。
- 结果：注释和文档称“64 位小写十六进制”，判据却允许 `a-z`，而十六进制字母范围应为 `a-f`。生成端自检虽然复用该谓词，但不能证明十六进制契约本身成立。当前生成的随机令牌仍属有效值，风险主要是协议误判及未来漂移。
- 修复：直接明确合法字符集，生成、验证、契约和测试统一为该域，并以边界字符来约束测试；无需数据迁移。
